# Restore point: snapshot-2026-11-13

Saved Friday, Nov 13 2026, before the sportsbook redesign. Saved on GitHub as the branch **`snapshot-2026-11-13`** (code commit `18dc12f3`). Nothing ever pushes to that branch, so it stays frozen.
If a redesign goes wrong, this puts the site back exactly as it was, without losing any tickets or data.

## What the site is at this point
- **Engine v4**: opponent-adjusted power ratings (Dixon-Coles family) on every game of the season, closing lines as evidence,
  soccer draw correction (rho -0.07), NFL key numbers, market-first logit blend, closing-line report card, "bet at X or better" prices.
- **Home**: grouped sport picker (11 sports; men then women; best-known leagues first, MORE searchable, COLLEGE at the bottom;
  youth leagues removed), VIEW switch with four layouts (Classic, Split, Tabs, Compact), Today's Games with a + on every team.
- **Corner slip**: + puts a moneyline on the slip; it waits bottom-right on every screen, survives a refresh, and is the same
  slip on NEW SLIP (Kalshi on).
- **Bet Slips**: NEW SLIP, MY BETS, LEADERBOARD, LIVE TICKETS, PAST TICKETS. Kalshi straights and combos (one tap, RFQ kept open),
  tickets record what Kalshi actually filled (fees included) and follow the real Kalshi position (bought more / sold in the app).
- **Live Tickets**: every Kalshi ticket shows its cash-out value to everyone; only the owner can cash out (two taps: CASH OUT,
  CONFIRM). Live stat bars (props, totals, spreads with the lead; moneylines turn the LIVE line green/red). TAIL under each ticket.
- **Kalshi sync**: open positions (incl. bought in the Kalshi app) become tickets; opt-in read-only server sync (encrypted key).
- **Refresh** returns to the same screen and tab. The site's day rolls over at 6 AM ET.
- Tests: 16 suites (`npm test`), plus browser checks used during development.

## How to go back to this point
The workflow deploys whatever is on `main`, and data snapshots keep committing, so restore the code only (never the data):

```bash
git fetch origin snapshot-2026-11-13
git checkout origin/snapshot-2026-11-13 -- src functions scripts tests index.html package.json .github README.md
git commit -m "Restore the site to snapshot-2026-11-13"
git push
```
The next run (about 5 minutes) deploys it. Or tell Claude: "restore the snapshot-2026-11-13 restore point". The download (`bobbys-boardroom-snapshot-2026-11-13.zip`) holds the same code.

To look at it without changing anything: `git checkout origin/snapshot-2026-11-13` (detached), `npm ci && npm run build`, open `index.html`.

## What a restore does NOT touch
- **Tickets, users, cash-outs, sync keys**: these live in Cloudflare D1 (`bobbys-boardroom-bets`), not in git. They stay as they are.
- **`data/`** (results, game archive, ratings, learned weights): keeps updating; the restored code reads it the same way.
- **Secrets** (names only): `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID` (GitHub Actions); `SYNC_SECRET` (Cloudflare Pages).
  Each person's Kalshi trading key stays on their own device (IndexedDB `bb-kalshi`), never on the server.
